# Stone Wealth：个人家庭最小版本与后续建议

## 当前服务范围

先服务一个家庭，成员继续通过已有统一登录获得 `asset-tracker` 服务权限，共用一套家庭资产数据。不开放陌生用户自助注册，也不把这套共享数据模型描述成多家庭隔离。正式网站由站长择期上线，本地开发使用独立数据库。

最小版本专注于：建立账户、录入和维护持仓与现金余额、查看标有页面生成时间和数据状态的家庭资产总览、保留操作记录与可恢复备份。页面生成时间不等于每项行情的抓取时间；具体行情状态仍以资产详情和数据状态页为准。Agent 授权是可选的高级能力，修改仍须在网站确认。家庭预算和计划与提醒暂不纳入范围。

### 可验收的家庭使用流程

1. 新家庭打开空白站点时，能看懂先建立账户、再添加第一笔资产的顺序；没有真实数据时不展示虚构金额。
2. 录入一笔现金或其他资产后，总览和账户金额随之更新；用户能找到数据异常与余额核对入口。
3. 资产的更新和归档走有校验、有审计记录的业务接口；旧接口不能绕过这些规则直接改写或硬删除资产。
4. 能对仍在使用的 SQLite 数据库做一致性备份，并在独立测试库中验证备份可打开、可恢复；备份文件不进入网页目录或 Git。
5. Agent 凭证只可读取资产、提交待确认建议，不能代替网站用户审批。

## 已完成、待部署验收的优化

- 账户加载/失败/重试反馈和归档后的总览刷新；资产与收支回收站。
- 所有网页业务写入的来源校验、首页防缓存及用户信息安全转义，保留现有统一登录。
- 总览与数据状态中的待核对清单：行情、汇率、数量、现金确认、Trading212 同步及对账问题；支持定位具体持仓。
- 账户、持仓、本月或全部收支 CSV 导出，保留原币与历史汇率，防止表格公式执行。
- 备份验证、运行记录、保留策略、过期/失败检查和每日任务模板；定时运行与外部通知仍需服务器配置，异地保管仍需另行安排。
- 使用临时模拟数据的浏览器测试及 GitHub 检查配置；推送后需确认远端运行结果。

## 个人家庭下一轮优化候选

按日常使用价值排序，不代表已实现：

1. **部署可靠性**：在服务器启用备份任务及失败/过期通知，安排异地副本、恢复演练和发布回滚。
2. **批量导入**：提供 CSV 导入预览、去重与回滚，减少手工录入；导出已实现。
3. **家庭协作权限**：同一家庭先区分只读成员与可编辑成员；重要修改保留操作者和时间。
4. **Agent 最小权限**：可按账户签发只读或可提建议的凭证，附使用记录与请求限速。
5. **手机安装体验**：补应用图标、安装引导和小屏幕核对流程；在没有真正的离线资产数据能力前，不宣称离线可用。

## 面向公众发布前另需完成

这些是跨家庭产品的门槛，不应在目前单家庭最小版本中假装已经具备：

- 建立家庭空间、成员邀请与角色，资产、账户、流水、快照、缓存、审计和 Agent 凭证都按家庭隔离；用跨家庭的反例测试覆盖全部接口。
- 保留现有统一登录作为身份来源，进一步收紧令牌在网址和浏览器脚本中的暴露，并确认退出、成员撤权与 Agent 凭证的联动。网页写入来源检查已完成，家庭角色与跨家庭权限仍需补齐。
- 设计自助首次使用与批量导入；若开放 Trading212 连接，改为逐家庭授权与凭证管理，不共用服务端的一把凭证。
- 明确数据保留、导出、删除、隐私告知及事件响应；依据目标地区和上架平台做合规核查。
- 建立自动备份、异地保管、恢复演练、运行监测和发布回滚流程；再邀请少量外部家庭试用。
